# Общий код ZX Evolution

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.en.md)
[![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

ASM-исходники в `src/<подсистема>/z80` реализуют адресацию ZX-битмапа, запись символов и пикселей,
отсечение линий Брезенхема и прямоугольников, обход эллипсов, побайтовые заливки, прокрутку
плоскостей, растровые шрифты и перемещение курсора. Эти исходники входят в оба архива. Каждая
конфигурация сама выбирает поверхность, отображает страницы и записывает данные в нужном формате.
Функции курсора работают с регистрами, подготовленными вызывающим кодом. Вызовы обхода линии нужно
сериализовать.

Публичные функции используют префикс `zx_`, внутренние функции и состояние используют `zx__`. Цвета
текста задаются через `zx_set_ink()` и `zx_set_paper()` из `include/zx/color.h`.
`zx_set_colors(border, ink, paper)` задаёт все три цвета сразу. `COLOR_BLACK` … `COLOR_WHITE` задают
индексы без сдвига, а `COLOR_BRIGHT` включает яркий вариант индекса. `zx_set_border_color()`
выбирает один из 16 цветов бордюра через код целевой конфигурации. В TSConf используется стандартный
ZX-банк F. [Цвета](include/zx/color.h)

Встроенные растровые шрифты доступны в обеих библиотеках как `zx_font8` и `zx_font5`. `zx/font.h`
также определяет дескриптор шрифта и объявляет таблицу узких глифов `zx_font5_data`.
[Шрифты](include/zx/font.h)

CRT вызывает `zx_init()` до `main()` и `zx_shutdown()` при выходе. Для явных вызовов собирайте с
`-pragma-define:CRT_ENABLE_ZX_LIFECYCLE=0`. Для стандартного ZX-битмапа выберите экран рисования
через `zx_select_draw_screen()`, а видимый через `zx_show_screen()`. Консоль использует одинаковые
координаты ячеек и результаты `zx_status_t` на обеих машинах. `zx_console_putc()` и
`zx_console_puts()` выводят с текущей позиции, а `zx_console_draw()` рисует по координатам ячейки
без перемещения курсора. Позиционный вывод останавливается у правого края или на первом байте
меньше 32. [Инициализация](include/zx/init.h) · [Видео](include/zx/video.h) ·
[Консоль](include/zx/console.h)

`zx_console_set_text_bg()` задаёт фон для посимвольного, строкового, форматированного и позиционного
вывода. Начальный режим — `ZX_TEXT_OPAQUE`. `zx_console_draw_op()` выбирает фон для одной строки.
Прозрачный вывод сохраняет пиксели вне глифа и атрибуты битмапа. Аппаратный текст не поддерживает
прозрачность. Рендерер `zx_font_t` получает режим фона последним аргументом.

`zx/graphics.h` предоставляет примитивы для рисования точек, линий, окружностей, эллипсов и заливки
прямоугольников, а также группы рисования, чтение пикселей и размеры поверхности. Функции с
суффиксом `_op` принимают `zx_draw_op_t` (`ZX_DRAW_SET`, `ZX_DRAW_CLEAR` или `ZX_DRAW_XOR`). В
упакованных режимах используются текущие цвета чернил и бумаги. Доступ к поверхности реализует
библиотека конфигурации. [Графика](include/zx/graphics.h)

`zx_blit4()` и `zx_blit4_key()` копируют линейные изображения packed 4bpp в поверхности BaseConf
ATM320 или TSConf 16C. CPU-backend поддерживает clipping, нечётные края и любой прозрачный индекс
0…15. Источник, код и стек должны оставаться резидентными; BaseConf требует заранее отобразить обе
страницы назначения для записи, TSConf временно занимает W3 и требует держать источник вне него.
Вызовы сохраняют палитру, цвета рисования и видимый экран. [Общий API blit](include/zx/blit.h)

Каждый архив содержит свою реализацию вывода для `zx_console_printf()`. При линковке обоих архивов
линковщик выбирает одну реализацию вывода и одну реализацию бордюра на всё приложение.

`zx/memory.h` предоставляет пул физических страниц RAM и страничную кучу. Выберите механизм
отображения страниц через `bc_ram_heap_init()` или `ts_ram_heap_init()`, затем используйте
`zx_ram_heap_*`. Выделение и освобождение возвращают `zx_status_t`. После каждой из этих операций
`zx_ram_heap_unmap()` подтверждает или повторяет восстановление окна. Пул страниц можно использовать
отдельно от кучи. [Память](include/zx/memory.h) · [Общие тесты](tests/README.ru.md)

`zx_acquire_ram(window, page, &lease)` временно отображает физическую страницу RAM;
`zx_acquired_ram_set_page(&lease, next_page)` меняет страницу в том же окне, а
`zx_release_ram(&lease)` восстанавливает исходное отображение. На TSConf доступны W2/W3, на BaseConf
— любое незакреплённое окно. `zx_pcm8_play_banked` использует этот контракт для последовательных
страниц и принимает окно и резидентную аренду от вызывающего кода. Частоту CPU и кэш вызывающий код
задаёт и восстанавливает сам. [Память](include/zx/memory.h) · [Аудио](include/zx/audio.h)

`zx_ay_select_chip(ZX_AY_CHIP_0)` выбирает первый AY TurboSound, `ZX_AY_CHIP_1` — второй.
Последующие обращения к регистрам и вывод PT3/AYFX идут в этот чип до следующего переключения. Выбор
не заглушает и не сбрасывает чипы, не определяет наличие оборудования, не создаёт отдельных
состояний плеера и не меняет IFF. Сериализуйте выбор вместе с последующими операциями AY
относительно обработчиков прерываний. Неверный номер возвращает `ZX_INVALID_ARGUMENT` без записи в
порты.

Для эффектов AYFX инициализируйте резидентный AFB-банк через `zx_ayfx_init()`, запускайте эффекты
через `zx_ayfx_play(index, volume_adjustment)` и вызывайте `zx_ayfx_frame()` с заданной частотой
кадров. Сериализуйте инициализацию и остановку с кадровым обработчиком; `zx_ayfx_play` защищает
изменение каналов внутри функции. На одном AY сначала обновляйте PT3, затем AYFX; на TurboSound
выбирайте нужный чип перед каждым плеером. `zx_ayfx_stop()` заглушает выбранный чип.

## Профиль запуска из BASIC 48

Для обеих конфигураций используются профиль zcc `-subtype=basic48` и общий CRT. Подключите
Make-фрагмент целевой библиотеки и передайте `$(BASECONF_BASIC48_FLAGS) -create-app` или
`$(TSCONF_BASIC48_FLAGS) -create-app`. Для прямого вызова zcc задайте `ZX_COMMON_ROOT` абсолютным
путём к этому каталогу и передайте пути к заголовкам и библиотеке и флаги ABI
`-clib=classic -compiler=sdcc --reserve-regs-iy`. Для BaseConf также задайте `BASECONF_ROOT`. Обе
конфигурации используют appmake из SDK. Перед упаковкой TAP прямым вызовом zcc соберите инструмент
командой `make appmake`.

```sh
make examples
```

Команда собирает примеры в `lib/baseconf/build/examples/` и `lib/tsconf/build/examples/`. Файлы
используют стандартный формат ZX TAP. Загрузчик выполняет `CLEAR 32767`, загружает плоский блок CODE
по адресу `8000h` и вызывает `RANDOMIZE USR 32768`.

CRT очищает BSS и использует стек BASIC ниже `8000h`. Инициализированная DATA входит в блок CODE.
BASIC задаёт начальное отображение страниц и состояние прерываний. Держите образ программы
доступным. Перед возвратом восстановите отображение ROM, рабочей области и стека BASIC, а также
состояние прерываний, если программа меняла их. CRT восстанавливает SP, IX и IY и передаёт код
выхода в BC. При ошибке инициализации `main()` пропускается, а её статус становится кодом выхода.
Если приложение завершилось с кодом ноль, ошибка `zx_shutdown()` становится кодом выхода. Перед
выходом завершите группы рисования и освободите удерживаемые окна.

Штатный CRT и профиль BASIC 48 по умолчанию запускаются с выключенным stdio. Для стандартных потоков
добавьте `-pragma-define:CRT_ENABLE_STDIO=1`.

Стандартный шрифт 8×8 берётся из ROM BASIC по адресу `3D00h`. При работе со шрифтом держите ROM
отображённым в W0. Для встроенного в программу шрифта соберите с
`-pragma-define:CRT_USE_ROM_FONT=0`.

В BaseConf нажмите `I` в меню ERS. В TSConf выберите `ROM #00` и `Basic 48` в настройках TS-BIOS,
затем выполните сброс. Подключите TAP для вашей конфигурации и введите `LOAD ""`. В обеих
конфигурациях `hello.tap` выводит приветствие на ZX-экран и возвращается в BASIC.
