# Инструменты ресурсов

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.en.md)
[![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

`convert.py` преобразует PNG, BMP, JPEG и другие изображения с одним кадром из форматов Pillow в
упакованные пиксели и палитру. Он также генерирует C или z88dk ASM из **любого бинарного файла**.
Конвертация, сжатие и генерация исходников — отдельные этапы; Z80 не декодирует PNG/BMP. Только
конвертация изображений связана с графикой. Сжатие и генерация исходников подходят также для музыки,
карт уровней, текста, таблиц и других бинарных ресурсов. Для сжатия используются внешние инструменты
z88dk; у `convert.py` есть команды `image`, `tiles`, `atlas`, `wav`, `emit` и `pack`.

Точка входа CLI регистрирует команды, вызывает обработчики и записывает возвращённые результаты.
Каждый модуль содержит свою логику преобразования, аргументы команды и обработчик:

| Модуль       | Назначение                                                                      |
| ------------ | ------------------------------------------------------------------------------- |
| `convert.py` | Регистрация команд, вызов обработчика, запись файлов и вывод путей/размеров     |
| `image.py`   | `image`: растровые изображения в индексированные пиксели и палитры              |
| `tiles.py`   | `tiles` / `atlas`: порядок тайлов, общая перенумерация индексов и сборка атласа |
| `audio.py`   | `wav`: PCM WAV в unsigned 8-bit mono                                            |
| `emit.py`    | `emit`: произвольные бинарные данные в C/ASM                                    |
| `pack.py`    | `pack`: ZX0-блоки, раскладка банков, генерация ASM/JSON                         |

Сборочные скрипты импортируют `convert_image` из `tools.assets.image`, `convert_wav` из
`tools.assets.audio` и `emit_source` из `tools.assets.emit` напрямую.

## Запуск и конвертация изображений

С установленным Python 3.11+ из корня репозитория:

```sh
./tools/assets/convert.py image picture.png \
  --output build/picture --format indexed4 --palette rgb555
```

Активация venv, команды pip и переменные Make не нужны. При первом запуске `image` или `atlas` общий
[модуль запуска Python](../python/README.ru.md) создаёт `tools/assets/build/python-requirements`,
устанавливает туда зависимости и перезапускает команду. Для первой подготовки нужен интернет либо
заполненный кеш pip/локальный индекс пакетов. Далее окружение переиспользуется; изменение
`requirements.txt` или версии Python запускает подготовку повторно. Сообщения подготовки выводятся в
stderr. `--help`, `wav`, `tiles`, `emit` и `pack` не подготавливают окружение Python; для `pack`
по-прежнему нужен внешний упаковщик z88dk.

Сборщики ресурсов примеров используют тот же модуль, поэтому достаточно `make examples-xnx` или
обычного `make` в каталоге XNX с исходным `python3`. При импорте функций как библиотеки ничего не
устанавливается: собственный CLI может вызвать `ensure_environment()` перед их использованием.

Команда создаёт `build/picture.bin`, `build/picture.pal.bin` и `build/picture.json`. Все команды
выводят абсолютный путь и размер каждого созданного файла. Относительные пути отсчитываются от
текущей рабочей папки, а не от папки изображения. У команды `image` параметр `--output c` задаёт
префикс имени: получатся `c.bin`, `c.pal.bin` и `c.json`. Для генерации исходника на C нужна
отдельная команда `emit`.

JSON содержит размеры изображения, шаг строки, глубину пикселя, формат палитры, прозрачность и
размер несжатых данных. Индексированные изображения по умолчанию сохраняют индексы палитры. Если
цветов слишком много, требуется явный `--quantize`: уменьшение числа цветов и перестановка палитры
не выполняются автоматически. При кодировании палитры младшие биты каналов отбрасываются до точности
выбранного аппаратного формата.

| Параметр                | Представление                                                                          |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `--format mono1`        | Восемь индексов на байт, левый пиксель в бите 7; без чередования строк экрана Spectrum |
| `--format indexed4`     | Два индекса на байт, левый пиксель в битах 7:4                                         |
| `--format indexed8`     | Один индекс на байт                                                                    |
| `--stride N`            | Шаг строки в байтах; после видимых пикселей добавляются нули                           |
| `--palette rgb222`      | Байт на цвет, `00RRGGBB`                                                               |
| `--palette rgb555`      | Слова little-endian, `0RRRRRGGGGGBBBBB` для CRAM TSConf                                |
| `--palette rgb888`      | Три байта на цвет: RGB                                                                 |
| `--transparent-zero`    | Индекс 0 для alpha=0; непрозрачные цвета перенумеровываются начиная с 1                |
| `--transparent-from 16` | Для старых индексированных спрайтов: исходные индексы ≥16 считаются прозрачными        |

Строки идут сверху вниз, пиксели — слева направо. Неиспользуемые биты последнего байта строки
заполняются нулями. Частичная прозрачность и анимация не поддерживаются: заранее наложите
изображение на фон, приведите альфа-канал к 0/255 или выберите один кадр. Это форматы ресурсов, а не
универсальная раскладка видеопамяти: ATM 320, экран Spectrum и атласы тайлов/спрайтов требуют
подходящего размещения. Примеры TSConf переносят компактные строки через DMA, который обеспечивает
аппаратный шаг строки назначения.

## Тайлы и атласы

`tiles` превращает упакованный битмап в последовательность тайлов: слева направо, затем сверху вниз.
Поддерживаются 1/4/8 bpp со старшими битами для левого пикселя и необязательный шаг исходной строки.
Размеры изображения должны быть кратны размерам тайла. Строки каждого тайла компактны; незанятые
биты последнего байта строки заполняются нулями.

```sh
./tools/assets/convert.py tiles build/picture.bin --width 320 --height 200 \
  --tile-width 8 --tile-height 8 --bits 4 --output build/picture_tiles
```

Создаются `.bin` и `.json`. Бинарник можно передать команде `pack` или `emit`.

`atlas` читает однокадровые индексированные изображения, разбивает их на тайлы и размещает в сетке
фиксированного размера. Сохраняется порядок входных файлов, внутри каждого — порядок тайлов по
строкам. Свободные ячейки заполнены нулями; неполные тайлы и переполнение атласа считаются ошибками.

```sh
./tools/assets/convert.py atlas player.bmp effects.bmp \
  --tile-width 16 --tile-height 16 --columns 32 --rows 4 --bits 4 \
  --transparent-from 16 --output build/sprites
```

Создаются `.bin`, `.indices.bin` и `.json`. В атласе индекс 0 зарезервирован для прозрачности.
`--transparent-from 16` считает исходные индексы от 16 прозрачными. Непрозрачные индексы всех
изображений сортируются и совместно перенумеровываются в 1…N; исходный непрозрачный ноль сохраняется
как обычный цвет. Один исходный индекс должен иметь одинаковый смысл во всех изображениях:
объединяются **индексы, а не RGB-палитры**. RGB-изображения, альфа-прозрачность и анимацию нужно
преобразовать заранее. Для `--bits 4` доступны максимум 15 непрозрачных индексов.

`.indices.bin` содержит исходные индексы: байт по смещению `выходной_индекс - 1` выбирает запись
исходной палитры. Этот же список записан в JSON как `source_indices`; это не RGB-палитра. Без
`--transparent-from` все использованные исходные индексы непрозрачны, но выходной ноль по-прежнему
зарезервирован.

Python-рецепты импортируют `split_tiles`, `build_atlas`, `remap_indices` и `convert_atlas` из
`tools.assets.tiles`. `split_tiles` возвращает поток байтов тайлов, `build_atlas` размещает такой
поток в сетке. `remap_indices` принимает буферы индексов по байту на пиксель и возвращает
перенумерованные буферы и таблицу исходных индексов. `convert_atlas` загружает изображения и
возвращает байты атласа, таблицу исходных индексов и метаданные. Pillow нужен только для загрузки
изображений.

## Звук WAV

Преобразование несжатого PCM WAV (8/16 бит, моно/стерео) в unsigned 8-bit mono:

```sh
./tools/assets/convert.py wav start.wav --output build/start
./tools/assets/convert.py emit build/start.bin --metadata build/start.json \
  --symbol start_sample --output build/start.h
```

Создаются `.bin` и `.json` с частотой, числом отсчётов, числом каналов и разрядностью. Частота
сохраняется, ресэмплинг не выполняется. Стереоканалы усредняются, 16-битные отсчёты приводятся к
восьми битам. Моно PCM8 сохраняется побайтно, включая нулевые отсчёты. Команда `wav` использует
только стандартную библиотеку. `emit` добавляет звуковые метаданные как константы рядом с массивом.
PCM8 передаётся напрямую в `zx_covox_play(samples, count, delay)`. `zx_pcm8_play_banked` проходит
последовательные физические страницы RAM через выбранное вызывающим кодом окно и восстанавливает его
отображение и IFF. Частоту CPU и кэш задаёт вызывающий код.

## Сжатие и генерация исходников

Сначала сожмите **бинарные данные** инструментом z88dk, затем сгенерируйте исходник:

```sh
z88dk-zx0 -f build/picture.bin build/picture.zx0
./tools/assets/convert.py emit build/picture.zx0 \
  --metadata build/picture.json --compression zx0 \
  --symbol picture --output build/picture.h

./tools/assets/convert.py emit build/picture.zx0 \
  --metadata build/picture.json --compression zx0 --language asm \
  --symbol picture --section BANK_80 --origin 0x80c000 --output build/picture.asm
```

Команде `emit` достаточно стандартной библиотеки Python. Результат для C — заголовок с защитой от
повторного включения, массивом `uint8_t` и константами размеров. ASM экспортирует `picture` и
`_picture`, содержит байты и константы размеров. Ресурс в `BANK_XX` должен помещаться в один банк 16
КиБ; большие ресурсы делите до сжатия. Сборщик ресурсов примеров показывает независимые блоки с
ограниченным размером после распаковки.

Для несжатых данных опустите `--compression`. Палитру можно вывести отдельно под другим именем. JSON
изображения описывает поток **пикселей**, поэтому не передавайте его при генерации исходника
палитры. Для ZX7 используйте внешний `z88dk-zx7` и параметр `--compression zx7`. Формат сжатия
задаётся явно, а не определяется по содержимому.

Для сжатого неграфического ресурса достаточно JSON с исходным размером в байтах, например
`{"unpacked_size": 4096}`. Графические поля необязательны. Для несжатых бинарных ресурсов метаданные
не нужны:

```sh
./tools/assets/convert.py emit level.bin --symbol level --output build/level.h
```

## Распаковка в приложениях SDK

Обе платформы SDK используют z88dk classic и могут подключать его распаковщики:

```c
#include <compress/zx0.h>
#include "picture.h"

/* destination must have PICTURE_UNPACKED_SIZE writable bytes. */
dzx0_standard((void *)picture, destination);
```

Используйте стандартный формат **ZX0 v2** от `z88dk-zx0` с соответствующим распаковщиком текущего
z88dk; не включайте `-c` для старого формата v1. Для ZX7 предназначены `<compress/zx7.h>` и
`dzx7_standard()`. Дублировать распаковщик или добавлять обёртку SDK не требуется. Исходные лицензии
кодеков находятся в z88dk.

Распаковщики не принимают длину и не проверяют входные данные. Используйте ресурсы, подготовленные
при сборке, выделяйте указанный объём для результата и держите оба буфера в доступном CPU адресном
пространстве без пересечений. Не меняйте отображение страниц во время распаковки; обработчик
прерываний должен его сохранять. Распаковывает CPU; DMA используется только для последующего
переноса в видеопамять.

TSConf DMA требует чётных адресов источника/назначения и чётной длины burst. Массив `uint8_t` в C не
обязательно выровнен: для буфера распаковки 2048 байт выделите 2049 байт и округлите указатель вверх
до чётного адреса. Разделяйте DMA на границах окон CPU, если соответствующие физические страницы
резидентной RAM не последовательны. Адрес самого сжатого потока может быть нечётным.

## Упаковка бинарных блоков и банков

`pack` принимает бинарные данные, не сгенерированные C/ASM. Он сжимает независимые ZX0-блоки,
раскладывает их по банкам 16 КиБ и выдаёт ASM-секции `BANK_XX`, бинарники банков и JSON с точными
packed/unpacked длинами и смещениями. Неявного padding в банках нет.

```sh
./tools/assets/convert.py pack image.bin --output build/image --chunk-size 2048 --first-page 0x80
```

Общие `pack_blocks`, `pack_banks`, `emit_banks` используются и рецептом ресурсов XNX. В рецепте
остаются списки и порядок ресурсов, размеры тайлов/атласа, настройки прозрачности, целевые страницы
и игровые таблицы. Извлечение тайлов, общая перенумерация индексов и сборка атласа находятся в
`tiles.py`, сжатие и раскладка банков — в `pack.py`.
