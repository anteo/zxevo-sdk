# Окружения инструментов Python

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.en.md)
[![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

`environment.py` готовит отдельные зависимости для консольных инструментов репозитория. Пользователь
запускает инструмент или `make` обычным способом, без активации venv и передачи пути к его
интерпретатору. Нужен Python 3.11+ с `venv`/`ensurepip`. Для первой подготовки требуется доступ к
пакетам через настроенный индекс или кеш pip. Системное окружение Python не изменяется.

## Подключение к инструменту

Поместите файл зависимостей рядом с инструментом. После разбора аргументов, но до импорта внешних
библиотек вызовите:

```python
from pathlib import Path
from tools.python.environment import ensure_environment

ensure_environment(Path(__file__).with_name("requirements.txt"))

# Здесь импортируются внешние библиотеки и выполняется команда.
```

Вызывайте функцию в точке входа CLI, а не при импорте модуля или внутри библиотечных функций.
Предварительный разбор аргументов позволяет вывести `--help` без установки. Команды, использующие
только стандартную библиотеку, должны пропускать этот шаг. Для короткой диагностики CLI может
перехватить `ValueError` и вызвать `parser.exit(1, f"{error}\n")`.

При запуске `python3 -m tools.some_tool.main` из корня SDK пакет `tools` уже доступен. Для прямого
запуска `tools/some_tool/main.py` можно сначала добавить корень репозитория:

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[2]))
```

Каталог окружения при необходимости задаётся явно:

```python
ensure_environment(requirements_path, directory=cache_path)
```

## Подготовка и повторный запуск

- По умолчанию используется `build/python-<имя requirements без расширения>` рядом с файлом
  зависимостей. Для `tools/assets/requirements.txt` это `tools/assets/build/python-requirements`.
- Модуль создаёт окружение и запускает его Python с `-m pip install -r`. Рабочий каталог pip —
  каталог requirements; действуют обычные настройки индекса и прокси pip. Рабочий каталог самого
  инструмента не меняется.
- В служебном файле сохраняются хеш содержимого переданного requirements, версия и база Python, путь
  окружения. Повторный запуск без изменений обходится без pip. Изменение переданного requirements
  или Python запускает подготовку повторно. Это не lockfile зависимостей; при необходимости
  фиксируйте версии в requirements.
- Подготовка защищена блокировкой на окружение, в том числе между отдельными процессами `make`.
  Неудачная установка не отмечается как успешная; следующий запуск повторяет попытку.
- Точка входа перезапускается подготовленным Python с исходными аргументами и рабочим каталогом,
  включая запуск через `python -m`. Перезапущенный процесс продолжает работу без повторной
  подготовки. Вызывайте функцию до побочных действий.
- Сообщения подготовки идут в stderr; stdout остаётся для результатов инструмента.

Кеш — удаляемый результат сборки, игнорируемый Git. Чтобы создать окружение заново, удалите его
каталог, когда инструмент не работает. Удаление пакета из requirements само по себе не удаляет уже
установленный пакет из окружения.

Модуль используют [конвертер ресурсов](../assets/README.ru.md) и оба рецепта ресурсов evosdk.
