# Расширение z88dk appmake для ZX Evolution

[![English](https://img.shields.io/badge/lang-en-blue.svg)](README.en.md)
[![Русский](https://img.shields.io/badge/lang-ru-green.svg)](README.ru.md)

SDK добавляет в z88dk appmake цели `+baseconf` и `+tsconf` для упаковки банковых TAP.
`+tsconf --format=spg` также создаёт программы SPG. Соберите инструмент из корня SDK, указав каталог
исходников z88dk.

```sh
make appmake Z88DK_SRC=/path/to/z88dk/src
```

Если `ZCCCFG` указывает на `lib/config` в этом дереве, `make appmake` найдёт каталог `src`. Скрипт
собирает временную копию appmake с `zxevo.c` и патчем `patches/zxevo-registration.patch`. Обе цели
доступны в `tools/appmake/build/z88dk-appmake`. Команда `make -C tools/appmake clean` удаляет
локальную сборку. Сборка также готовит отдельный [инструмент mhmt](../mhmt/README.ru.md) в
`tools/mhmt/build/`.

Нужны C-компилятор для хоста, `make`, `patch` и файлы разработки GMP. Скрипт берёт флаги GMP из
`pkg-config`, если он доступен, и использует `-lgmp` при отсутствии флагов линковки. В `Z88DK_SRC`
должны быть `appmake/`, `common/dirname.c`, `common/dirname.h` и `config.h`.

## Происхождение и лицензия

Упаковщик разрабатывался для z88dk версии `26724-9fc3cae210-20261103`. Через `Z88DK_SRC` можно
указать другое совместимое дерево. Скрипт выводит версию при сборке. Исходники appmake и их
уведомления берутся из этого дерева. Лицензия z88dk Clarified Artistic License находится в файле
`LICENSE` на уровень выше `Z88DK_SRC`. Патч фиксирует изменение регистрации, а исходник нового
упаковщика находится в этом репозитории. Встроенные исходники `mhmt` имеют отдельную лицензию GPLv3
и собираются в отдельный исполняемый файл.

## Упаковка TAP

В обеих конфигурациях `APPMAKEEXE` выбирает appmake из SDK. Для обычных TAP под BASIC 48
используется его стандартная цель `+zx`. В Makefile подключите фрагмент нужной конфигурации и
добавьте `$(ZX_APPMAKE_BIN)` в зависимости правила сборки TAP.

Для банкового TAP передайте `-Cz+baseconf` с `$(BASECONF_APP_FLAGS)` или `-Cz+tsconf` с
`$(TSCONF_APP_FLAGS)`. Пример команды в правиле сборки TSConf.

```makefile
	$(ZCC) $(TSCONF_APP_FLAGS) \
	  -pragma-define:CRT_ORG_CODE=0x8000 -m -create-app -Cz+tsconf \
	  -Cz--name=MYPROGRAM -o build/program src/main.c
```

Добавьте настройки линковки для своих банков RAM. Чтобы использовать CRT с возвратом в BASIC 48,
добавьте `-crt0=$(ZX_COMMON_ROOT)/crt/basic48_crt0.asm` к флагам приложения. Переменные
`*_BASIC48_FLAGS` уже выбирают цель `+zx` для плоских TAP, поэтому для банковых сборок возьмите за
основу `*_APP_FLAGS`.

Для упаковки уже слинкованной программы вызовите инструмент напрямую с `+baseconf` или `+tsconf`.

```sh
tools/appmake/build/z88dk-appmake +tsconf \
  --binfile build/program --crt0file build/program --output build/program.tap
```

Файл карты и бинарники секций должны лежать рядом и иметь стандартные имена z88dk appmake. Упаковщик
берёт адреса и размеры из карты линковки.

## Упаковка SPG

SPG — запускаемая напрямую программа TSConf с физическими блоками RAM и начальными регистрами.
Используйте `+tsconf --format=spg`: одно расширение выходного файла не переключает формат. Данные
берутся из той же карты и бинарников секций, что используются для упаковки TAP:

```sh
tools/appmake/build/z88dk-appmake +tsconf --format=spg \
  --binfile build/program --crt0file build/program --output build/program.spg \
  --name=MYPROGRAM --spg-stack=0x8000 --spg-page3=0 --spg-resident=0x5b00 \
  --spg-compression=auto
```

Собирайте автономное приложение с общим Z80 CRT, который выбирают `TSCONF_APP_FLAGS`:

```makefile
program.spg: src/main.c $(TSCONF_LIB) $(ZX_APPMAKE_BIN)
	$(ZCC) $(TSCONF_APP_FLAGS) -pragma-define:CRT_ORG_CODE=0x8000 \
	  -pragma-define:CRT_ENABLE_STDIO=0 -m -create-app -Cz+tsconf \
	  -Cz--format=spg -Cz--spg-stack=0x8000 -Cz--spg-page3=0 \
	  -Cz--name=MYPROGRAM -o program src/main.c
```

Не выбирайте `*_BASIC48_FLAGS` или `basic48_crt0.asm`: вход в SPG не происходит через BASIC `USR`,
адреса возврата в BASIC на стеке нет. Перепаковка TAP с возвратом в BASIC не адаптирует его код
запуска к SPG. Общий автономный CRT сохраняет SP из заголовка SPG, если приложение не переопределило
настройку стека; по умолчанию выход заканчивается циклом HALT. Загрузчик отображает ROM BASIC 48 в
W0, RAM 5 в W1, RAM 2 в W2, выбранную страницу в W3, устанавливает ZX-экран 0, IM1 и I=3Fh. Это
**не** инициализирует сеанс BASIC и его рабочую область. Приложение должно настроить видео, палитру,
TSU, периферию и обработчик прерываний перед включением прерываний. При входе оставляйте прерывания
выключенными, если приложение явно не подготовило обработчик и нужную ему память. Обработчик IM1 из
BASIC, ROM I/O и обычный `RET` не могут рассчитывать на среду запуска TAP.

| Параметр            | Значение по умолчанию / назначение                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `--format=spg`      | Формат SPG 1.0; только для `+tsconf`                                                             |
| `--name`            | `TSCONF`; описание, 1–32 байта                                                                   |
| `--usraddr`         | Символ `start`, иначе первый инициализированный адрес; точка входа CPU в `4000–FFFF`             |
| `--spg-stack`       | `0x8000`; начальный SP, стек растёт вниз                                                         |
| `--spg-page3`       | `0`; физическая RAM в `C000–FFFF` при входе, диапазон `00–DF`                                    |
| `--spg-resident`    | `0x5b00`; резерв 16 байт для резидента загрузчика                                                |
| `--spg-clock`       | `0`: 3,5 МГц; `1`: 7 МГц; `2`: 14 МГц; `3`: режим 14+ из upstream                                |
| `--spg-interrupts`  | Включить прерывания при входе; по умолчанию выключены                                            |
| `--spg-compression` | `none` (по умолчанию), `auto`, `mlz` или `hrust`; `auto` пробует оба формата для каждой страницы |
| `--spg-compressor`  | По умолчанию собранный `tools/mhmt/build/mhmt`; можно задать другой исполняемый файл             |

Упаковщик делит резидентный загрузочный образ по границам окон CPU и размещает его в физических
страницах 5, 2 и `--spg-page3`. Ресурсы `BANK_XX` сохраняют явно заданные физические страницы.
Каждая занятая страница становится одним блоком с выравниванием и нулевым дополнением до секторов по
512 байт. При включённом сжатии appmake вызывает `mhmt` для каждой страницы, записывает штатный тип
MegaLZ/Hrust и оставляет сырой блок, если сжатие не экономит полный сектор. `auto` выбирает
минимальное число секторов; при равенстве предпочитает MegaLZ. При запуске appmake по пути из SDK он
использует локально собранный `mhmt`; другой путь можно задать через `--spg-compressor`. Загрузчик
SPG распаковывает блоки до входа в приложение, поэтому адреса кода и PT3 сохраняются. Промежутки
внутри блока заполняются нулями. Пересечение резидентных и банковых данных отклоняется, как и
страницы `E0–FF`, зарезервированные SPG для загрузчика. BSS не записывается. Резидент загрузчика и
первое слово стека не должны пересекать данные (включая выравнивание секторов) или BSS. Ниже SP
нужно дополнительно оставить место для всего стека приложения: его глубину упаковщик определить не
может. Необязательный pager не устанавливается (`pager=0`). Для воспроизводимого результата дата
заголовка фиксирована: 2000-01-01 00:00:00. По умолчанию результат получает имя входного файла с
расширением `.spg`. Для SPG `--org` должен совпадать с адресом загрузки из карты линковки. Для
переноса программы перелинкуйте её с нужным `CRT_ORG_CODE`: изменение адреса загрузки не переносит
абсолютные ссылки и BSS.

Сырые ресурсы в секциях `BANK_XX` можно сжать средствами контейнера SPG без распаковщика в
приложении. Уже сжатые ресурсы ZX0/ZX7 остаются сжатыми байтами внутри блоков и по-прежнему требуют
распаковщик приложения. Расширения SPG 1.1 для картинки/секций RO/RW не генерируются. Опции
`--clearaddr` и `--bank-prefix` действуют только для TAP и отклоняются для SPG.

Реализация следует `pentevo/docs/Formats/SPGv1_0.txt` и исходному `spgbld` из
[репозитория TSConf](https://github.com/tslabs/zx-evo/tree/f0eebed4edb4f36d0e6368363376b317f5a83083/pentevo).
Формат записывается напрямую, без запуска Windows-упаковщика SPG.

## Тесты банковых TAP

Набор appmake запускается отдельно от тестов библиотек.

```sh
make test-appmake ZESARUX=/path/to/zesarux ZXEVO_TEST_ROM=/path/to/ZXEVO.ROM
```

Тесты собирают банковый TAP для каждой конфигурации и выполняют `LOAD ""` в BASIC 48. Они проверяют
байты в обеих физических страницах RAM, отображение W3 при входе и возврат в BASIC. TAP и журналы
сборки и эмулятора находятся в `tools/appmake/build/tests/`. Если не задать `ZXEVO_TEST_ROM`, будут
использованы ROM из эмулятора.

## Формат TAP и загрузка

- TAP содержит токенизированный загрузчик Spectrum BASIC и стандартные блоки CODE.
- Загрузчик и основной блок по умолчанию называются `BASECONF` или `TSCONF`. Опция `--name=NAME` или
  флаг zcc `-Cz--name=NAME` задаёт имя из 1–10 символов. Поле дополняется до 10 байт. Имена банков
  по умолчанию имеют вид `BANK000`–`BANK255`. Для другого префикса из 1–7 символов используйте
  `--bank-prefix=PREFIX` или `-Cz--bank-prefix=PREFIX`.
- Инициализированные секции основного банка собираются в один образ с нулевым заполнением
  промежутков. BSS не входит в загрузочный образ.
- Загрузчик BaseConf использует настройки RAM и частоты CPU, оставленные ERS/BAS48. Для каждого
  банка он открывает теневые порты, отображает физическую страницу в W3 (`C000–FFFF`) без
  подстановки и восстанавливает `BF` перед чтением с ленты. В W3 остаётся последняя загруженная
  страница.
- Загрузчик TSConf сохраняет Page3, отображает банк через порт `13AFh`, загружает его и
  восстанавливает прежнее значение Page3.
- По умолчанию загрузка начинается с первой инициализированной секции, а `USR` входит по символу
  `start`. При отсутствии `start` используется адрес загрузки. `start` включает код запуска CRT.
  `__CODE_head` указывает на начало кода после CRT. Значение `CLEAR` по умолчанию равно `0x5fff`.
  Адреса переопределяются через `--org`, `--usraddr` и `--clearaddr`.
- Секции каждого банка объединяются в образ для W3 размером до 16 КиБ. Банки загружаются по
  возрастанию номеров. Номер физической страницы для `BANK_XX` берётся из старшего байта адреса
  секции z80asm.

Основной образ должен помещаться в 16-битном адресном пространстве. При загрузке резидентный код,
рабочая область и стек BASIC должны оставаться доступны. Для банков выбирайте свободные физические
страницы конфигурации.
